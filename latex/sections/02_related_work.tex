\section{Related work}
\label{sec:related-work}

\paragraph{Railway disruption prediction.} Most published work on operational railway analytics calibrates a single-country, single-operator model on a homogeneous internal data feed~\cite{gerum2024railway}. Cross-operator harmonisation is rarely addressed because the same nominal feature -- ``weather severity'', say -- carries different semantics across operators when its underlying observations come from different national meteorological services. Italy's internal weather codes, Finland's FMI station readings, and the Netherlands' Open-Meteo Historical Archive~\cite{zippenfenig2023openmeteo} use different missingness conventions and different physical units. We therefore invest substantial engineering effort in an anti-leakage Common Data Model (\cref{sec:features}) before any model is trained, and treat that harmonisation step as an explicit deliverable rather than a footnote.

\paragraph{Tabular gradient-boosted ensembles.} For spatio-temporal tabular problems with tens of millions of rows, the strongest baselines remain LightGBM~\cite{ke2017lightgbm} and XGBoost~\cite{chen2016xgboost}: gradient-boosted decision-tree systems that scale linearly through histogram-based split-finding. Their dominance over neural alternatives on heterogeneous tabular data is by now well established, so we use them as default baselines. We also include a Random Forest~\cite{breiman2001random} as a low-bias variance reference.

\paragraph{Graph and sequence models.} Two non-tabular families are also benchmarked. GraphSAGE~\cite{hamilton2017inductive} tests whether the station-adjacency graph (\num{2398} nodes, \num{163902} directed edges) carries signal beyond the static centrality features that summarise it. A bidirectional / causal LSTM~\cite{schuster1997bidirectional,hochreiter1997long} is the natural sequence baseline; we implemented it but defer the full benchmark for the memory reasons explained in \cref{sec:models}.

\paragraph{Explainability.} We use TreeSHAP~\cite{lundberg2017unified,lundberg2020local}, the canonical exact-attribution method for tree ensembles, applied to a stratified \num{270644}-row sample (10\% of the \num{2706443}-row test set, fixed seed) for tractable wall-clock on a wide gradient-boosted ensemble. The full-test-set attributions both stabilise the global feature importance ranking and provide the per-row local attributions that the Knowledge Graph bridge query (\cref{sec:kg}) consumes.

\paragraph{Graph databases.} The Knowledge Graph runs on Sparksee~\cite{sparksee2024} (the descendant of DEX~\cite{martinez2017dex}). Sparksee's vendor distribution is gated behind a registered-user login, but its JVM bindings are also published on Maven Central as \texttt{com.sparsity:sparkseejava:5.2.3}, which already bundles the Linux x86\_64 native libraries. We drive that JVM binary from Python via JPype1, which gives the entire pipeline a one-shell-command install path and removes the registration barrier from the reproducibility story. Schema and bridge-query semantics are portable to any Cypher-compatible store; only the driver call sites differ if the reader prefers Kuzu~\cite{feng2023kuzu} or Neo4j.

\paragraph{Cross-country transfer.} Operational machine learning routinely faces the problem that the source-operator feature distribution does not match the target operator. We document one such failure in \cref{sec:transfer}: a Netherlands-trained cause classifier never predicts the rare \emph{weather} class on Finnish stops, even though Finland has a much harsher winter. The root cause is a numerically incompatible scale between Open-Meteo daily aggregates and FMI hourly observations. Negative-result documentation of this kind contributes to the practical literature on when domain-naive transfer is unsafe and what minimum alignment effort makes it safer.
