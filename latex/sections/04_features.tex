\section{Feature engineering and anti-leakage}
\label{sec:features}

\subsection{The Common Data Model}

After Phase~1, every country's processed/ folder contains the same five CSV files: \texttt{nodes\_station}, \texttt{nodes\_service}, \texttt{edges\_stops\_at}, \texttt{edges\_adjacent} and \texttt{nodes\_fault}. Phase~2 (\texttt{stop\_level/preprocess\_stops.py}) loads these 15 CSVs (5 schemas $\times$ 3 countries), joins them at stop grain, computes 16 feature groups, fits a \texttt{StandardScaler} on training rows only, and persists a parquet feature store to \texttt{Data/stops/}.

\subsection{Anti-leakage protocol}

The pipeline turns on one rule: at prediction time, the feature vector $\mathbf{x}$ may only contain information that was actually available before the prediction is made. Several layers enforce it:

\begin{enumerate}
    \item Phase~1 keeps \texttt{delay\_minutes} only as a column to derive labels from; it is never persisted as a feature in the parquet output.
    \item Phase~2 defines two sets \texttt{LEAKY\_COLS\_A} (15 columns) and \texttt{LEAKY\_COLS\_B} (11 columns; A minus the 3 inflight whitelist plus \texttt{headway\_to\_train\_ahead}) and asserts the active feature list does not intersect them \emph{before} fitting the scaler.
    \item All lag features use \emph{strict} \texttt{<} on the daily aggregation grid: \texttt{station\_lag1\_rate(D)} sees only data from $D-1$ and earlier, never $D$. This invariant is unit-tested.
    \item The temporal split is day-level so a \texttt{service\_id} never crosses the train/val/test boundary.
    \item The \texttt{StandardScaler} is fit on \texttt{X\_train} only; \texttt{X\_val} and \texttt{X\_test} are transformed but never re-fit.
    \item Per-scenario feature lists are persisted as \texttt{feature\_names\_\{A,B\}.json} so any downstream consumer (model, SHAP, ablation) reads the same contract.
\end{enumerate}

\subsection{Memory engineering}

The 16.6\,M-row $\times$~47-column dataframe initially exceeded \SI{15}{GB} RAM. Three concrete fixes shipped during this run:
\begin{enumerate}
    \item Compact dtypes on load: float64\,$\to$\,float32 ($\sim$50\,\% saving), small ints down-casted to \texttt{int8/32}, string IDs to \texttt{category}.
    \item Map-based stop-grain join (\texttt{Series.map(dict)} instead of \texttt{pd.merge}) avoids the multi-GB intermediate hash that pandas materialises for two~\num{1}~M+-key categoricals.
    \item Eight redundant \texttt{df = df.copy()} calls in feature builders removed; the chained-flow pattern \texttt{df = F.add\_*(df)} is safe to mutate in place.
\end{enumerate}
A high-cardinality fallback in \texttt{compute\_train\_lag} skips the contiguous-calendar grid when the unique-key count exceeds 50K (NL has $\sim$1\,M unique train keys, so the default grid would be 215\,M rows).
