\section{Cause-of-disruption prediction}
\label{sec:cause}

\subsection{Task definition and labelled data}

The Netherlands publishes a separate disruption-incident log that tags each event with a \texttt{cause\_group} drawn from nine mutually-exclusive classes: \emph{rolling stock, infrastructure, external, accidents, unknown, logistical, engineering work, staff, weather}. Italy and Finland do not publish equivalent labels. We construct a labelled Dutch dataset by joining each disrupted Dutch stop to the most-frequent \texttt{cause\_group} reported at the same station on the same date. The result contains \num{126810} labelled stops, which is \SI{32.2}{\percent} of all Dutch disrupted stops; the remainder are disrupted but unlabelled, an important caveat we return to in \cref{sec:discussion}.

The class distribution is severely skewed (\cref{tab:cause-classes}). Rolling stock alone accounts for almost two in five labelled stops; weather, despite being operationally important, accounts for only one in ninety. The skew motivates the design choices in the next subsection.

\subsection{Design choices}

Five design choices target the failure modes the class skew induces -- collapse onto the majority class, complete silence on rare classes, and absent winter-weather signal.

\begin{enumerate}
    \item \textbf{Cause-specific feature engineering.} 23 features tied to known causal patterns: peak-hour flags, weekend / Monday / Friday flags, season indicators, log-transformed delay, severe-delay flags ($>$\,30 and $>$\,60 minutes), cascade indicators derived from \texttt{prev\_stop\_actual\_delay}, severe-weather flags (\texttt{weather\_severity}~$\geq$~3 and~$=$~4), a heavy-snow flag, and the interaction \texttt{winter\_x\_severe\_weather}. The last is the single most important addition (see results).
    \item \textbf{Symmetric sample weighting.} \texttt{\seqsplit{sklearn.utils.class\_weight.compute\_sample\_weight}}\linebreak[2]\texttt{('balanced',\ y\_train)} is computed once and passed as \texttt{sample\_weight} to LightGBM, XGBoost, random forest and gradient boosting. The boosted models therefore see rare classes as expensive to misclassify, not just the linear and forest models.
    \item \textbf{Hyperparameter tuning for an imbalanced target.} The boosted models use 800 trees, deeper splits (\texttt{num\_leaves}~$=$~127, \texttt{max\_depth}~$=$~8 for XGBoost), and L1/L2 regularisation set to \num{0.1}.
    \item \textbf{Five-base benchmark.} Logistic regression, LightGBM, XGBoost, random forest, and sklearn's gradient boosting are trained on the Phase~2 splits (\num{84606} train, \num{22291} validation, \num{19913} test rows). The gradient-boosted addition is included because its bias profile differs slightly from XGBoost and LightGBM.
    \item \textbf{A stacking ensemble.} A logistic-regression meta-learner is fitted on the validation-set probability outputs of all five base models.
\end{enumerate}

\subsection{Results}

\Cref{tab:cause-results} reports the benchmark. LightGBM is the test winner with macro-F1 of \num{0.213}; the stacker leads on validation but overfits, dropping to \num{0.137} on test -- a textbook example of why a separate held-out is necessary when a meta-learner is involved.

The per-class breakdown (\cref{tab:cause-perclass}) is the more interesting view. The rare \emph{weather} class reaches F1$=$\num{0.509}, attributable to the single \texttt{winter\_x\_severe\_weather} interaction feature: without it the model never predicts \emph{weather} at all. The class skew is also why the dominant \emph{rolling stock} class sits at F1$=$\num{0.425}: under symmetric sample weighting the model no longer uses it as a default-everything fallback, which costs precision on rolling stock but buys recall on the rare classes. \emph{Engineering work} remains unsolved -- with only 235 test examples and a temporal pattern that overlaps with \emph{logistical}, the current feature set cannot disambiguate the two.
